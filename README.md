# Hikari — 太陽光 最適容量プランナー

お客様の暮らし方（家族構成・空調の使い方・ペット・EV/V2H・蓄電池・停電への備え）と、
地域・屋根・パネル機種から、**「何kW載せるのがベストか」を根拠付きで算出**するツールです。

- 気象庁の実測データ（全国63地点）× JPEA（太陽光発電協会）表示ガイドラインの計算式で発電量を推定
- 機器ごとの積み上げで消費量を推計（24時間空調・全館空調・エコキュート・EV など）
- 365日×24時間で自家消費・売電・蓄電池/V2H をシミュレーション
- パネルを1枚ずつ増やして20年収支を比較し、**経済性・ネットゼロ・屋根上限・停電対策**の4基準で推奨容量を決定
- ヒアリングの最後に、お客様向けの**A4・6ページの提案書（PDF）**が出来上がります

計算の考え方と数値の出典は **[docs/根拠と計算方法.md](docs/根拠と計算方法.md)** にまとめています。

## 使い方

### いつでも使う（claude.ai）

**https://claude.ai/artifact/1gpLGs42CkHd1SGKxPrfg6**（サイドバーにピン留め済み）

- どのPCでも、claude.ai にログインすれば開けます。お客様データはアーティファクトのデータベースに保存され（所有者だけが読み書き可）、別のPCでも同じ一覧が出ます
- 「PDFで保存」で提案書をPDFファイルとして保存します
- 更新するときは `python3 tools/build_artifact.py` で `dist/hikari.html` を作り直して再公開します

### 起動（ローカル）

インストール不要です。`index.html` をブラウザ（Chrome / Edge 推奨）で開くだけで動きます。
（フォントは Google Fonts から読み込みます。オフラインでも端末のフォントで表示・計算できます）

```bash
# ローカルサーバーで開く場合（任意）
python3 -m http.server 8000   # → http://localhost:8000/
```

### 流れ：お客様情報 → ヒアリング → 提案書（PDF）

1. **ホーム**：右上の「提案者情報」で会社名・担当者・連絡先を一度だけ登録（表紙と最終ページに入ります）
2. **新しいお客様の提案をつくる** → 6ステップのヒアリング
   | STEP | 内容 |
   |---|---|
   | 01 お客様情報 | お名前・敬称・提案日・都道府県・市区町村（全国1,738）・住所・担当者 |
   | 02 お住まいとご家族 | 使い方（ご家族の住まい／終の棲家／セカンドハウス）・人数・日中の過ごし方（シニア世代を含む）・延床面積・断熱性能・年齢 |
   | 03 屋根とパネル | 屋根の形・向き（方位ダイヤル）・勾配・屋根面ごとの枚数・メーカー機種 |
   | 04 空調と暮らし | ペット・冷暖房の方式（壁掛け／全館空調）・部屋ごとのエアコン・冷暖房の使い方・暖房の主役・こたつ等・給湯・家事家電 |
   | 05 EV・蓄電池・停電 | 蓄電池（Qセルズ／長州産業／ニチコン）・EV・V2H機器・停電時に使いたいもの |
   | 06 方針と費用 | 提案の目的・太陽光の費用（基本費用＋1kWあたり−補助金）・電気料金 |
   - 右側のパネルに、入力に合わせて **推奨容量がリアルタイムに表示** されます
3. **提案書をつくる** → A4・6ページの提案書をその場でプレビュー
   1. 表紙（お客様名・推奨容量）
   2. ご提案の結論（4つの数字・電気のゆくえ・ポイント）
   3. なぜこの容量か（3つの目安・容量ごとの手残り・判断の材料）
   4. お金の流れ（手残りの推移と回収・期間ごとの経済効果の内訳）
   5. 暮らしと発電（電気の使い道・月別・停電への備え）
   6. 計算の前提と用語・提案者情報
   - 「詳細資料を付ける」で、屋根の割り付け・容量別の比較表・1日の流れを1ページ追加（営業用）
4. **PDFで保存** → 印刷画面で「送信先：PDFに保存」を選ぶと、そのままPDFになります
   （ファイル名は「太陽光発電ご提案書_お客様名」）

お客様データは自動でこのブラウザ（localStorage）に保存され、ホームの一覧から「提案書」「ヒアリング」「複製」「削除」ができます。
別のPCへ移すときは提案書画面の「データ書き出し」→ ホームの「読み込む」。

## 前提値の変更

- 機器の消費量・パネル機種・単価などの既定値：`js/data/catalog.js`
  - パネル機種は代表値です。**提案前に必ず最新カタログの公称最大出力・外形寸法・温度係数を確認**してください
- 気象データの再取得（通常は不要）：

```bash
cd tools
python3 fetch_jma.py      # 気象庁 平年値（日射量・気温）を取得 → jma_normals.json
python3 fetch_pvgis.py    # PVGIS の傾斜面日射量を取得（約3,000リクエスト・数分）→ pvgis_cache.json
python3 build_climate.py  # js/data/climate.js を生成
python3 fetch_municipalities.py  # 全国の市区町村と代表点（Wikidata）
python3 fetch_pvgis_monthly.py   # 市区町村ごとの月別日射量・気温（約1,800リクエスト）
python3 build_munis.py           # js/data/munis.js を生成
```


発電量の水準（東京・南30°で1kWあたり1,050〜1,300kWh）、方位・地域差、エネルギー収支の整合、

## ファイル構成

```
index.html              画面（ホーム / ヒアリング / 提案書）

js/engine.js            計算エンジン（発電・消費・需給・経済性・推奨）
js/proposal.js          提案書（A4×6ページ）の組版と説明文
js/store.js             保存（データベース／ブラウザ内）とPDF・ファイル書き出し
dist/hikari.html        claude.ai アーティファクト用の1ファイル版（tools/build_artifact.py で生成）
js/app.js               画面制御・保存
js/charts.js            グラフ描画（SVG、外部ライブラリなし）
js/data/climate.js      気象データ（自動生成）
js/data/catalog.js      機器・パネル・制度の前提値
docs/根拠と計算方法.md   計算方法と出典
tools/                  気象データの取得・生成スクリプト
tests/                  テスト
```

## 注意

本ツールの結果は推計です。実際の発電量・電気代は、天候、影、積雪、出力制御、使い方、機器の性能によって変わります。
最終的な提案では、メーカーのシミュレーションや現地調査の結果と合わせてご確認ください。
