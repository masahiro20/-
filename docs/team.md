# ふくしのおたすけ帳 運営チーム

サイトを「止まらずに良くし続ける」ためのチームです。メンバーはAI（Claude）の役割分担で、あなた（オーナー）は方針の決定と、アカウントやお金が関わる操作だけを担当します。

## 体制

| 役割 | 担当 | やること |
|---|---|---|
| オーナー | あなた | 方針を決める。アカウント登録・支払い・公開範囲の変更など、本人にしかできない操作。意見箱やSNSの声を共有する |
| プロジェクトマネージャー（PM） | Claude（このセッション） | バックログの優先順位を決め、制作スタッフに仕事を割り振る。品質チェックの結果を見て公開を判断し、毎週報告する |
| 制作スタッフ（ツール） | Claude のサブエージェント（1人1ツール） | 新しいテンプレートを1つ作る（`data/templates/<id>.mjs` と `site/assets/tpl/<id>.js`）。担当以外のファイルは触らない |
| 制作スタッフ（使いやすさ） | Claude のサブエージェント | 検索・保存・表示の改善など、サイト全体の使いやすさを担当（`formdoc.js`・`common.js`・`style.css`・`build.mjs`） |
| 品質管理スタッフ（QA） | Claude のサブエージェント | 公開前に、内容の正しさ（制度・用語）、スマホでの見え方、リンク切れ、文章の分かりやすさを確認し、直すべき点を一覧にする |

## 動き方（スプリント）

週2回（水・土の朝 8:47、日本時間）に自動で始まり（Claude の定期実行「おたすけ帳 改善スプリント」）、PMが次の順に回します。毎週月曜 8:52 にはアクセス数の報告があります。オーナーの承認は待たずに公開まで進めます（方針の変更・お金・アカウントが関わるものだけ確認）。

1. **選ぶ**：`docs/team/backlog.md` から、効果が大きいもの（意見箱の声 → 検索で探されている書類 → 使いやすさ）を3〜4件選ぶ。
2. **作る**：制作スタッフが並行して作る。1人1件・担当ファイルだけ。
3. **確かめる**：QAが全ページをブラウザで開いて確認（全ツールの下書き・印刷・スマホ幅・リンク）。指摘は制作スタッフかPMが直す。
4. **出す**：ビルド → コミット → 本番（Vercel）に公開 → 本番でもう一度確認。
5. **記録する**：バックログを更新し、完了したものを「リリースの記録」に書く。新しいツールはSNSで「できました」と告知できるよう、一言の紹介文を残す。

## 品質の決まり（全員が守ること）

- **入力は送信しない**：入力内容は利用者の端末から外に出さない（保存するときも、その端末の中だけ）。
- **制度の根拠を書く**：加算・基準・様式に触れるときは、出典（省令・通知・Q&A）をページの「出典」に書く。分からないことは断定しない。
- **専門用語はやさしく**：初めて読む新人職員にも分かる言葉で。カタカナ語や略語は、言い換えるか説明を添える。
- **スマホで使える**：幅360pxで横にはみ出さない。ボタンは指で押せる大きさ。
- **書類の中に広告を入れない**：PR枠は業種ページの下だけ。
- **個人情報に注意**：記録の例文に実在の人名を使わない。氏名欄は「〇〇さん」などにする。

## 新しいツールの作り方

`docs/deploy.md` の「9. 新しいテンプレートの足し方」と、既存のテンプレート（例：`site/assets/tpl/kesseki.js`）を参考にする。
`data/templates/<id>.mjs` を置けば、ページ・業種ページの一覧・フッター・サイトマップに自動で入る。
